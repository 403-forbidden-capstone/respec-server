# 종료 런북 (초안) — AWS 를 전부 끊는 순서

AWS 무료 플랜이 끝나는 **2027-03-03 전에** 서버 · 옛 빵모아 인스턴스 · 관련 리소스를 전부 지우는 순서.
목표는 "그날 누르는 버튼이 몇 개 안 되게": 되돌릴 수 있는 것은 **며칠 전**에 미리 끝내 두고, **그날**에는 되돌릴 수 없는 삭제만 함.

- 실제 날짜는 지형님이 정함. 권장: 종료일 2주 전(2027-02-17)까지 끝내고, 남은 2주는 청구서가 $0 인지 보는 기간. 무료 플랜 종료일은 콘솔에서 확인(U5 메모).
- 표의 **되돌림**: 가능 = 같은 화면에서 다시 만들거나 값을 되돌리면 됨 / **불가** = 지우면 끝(새로 세워야 함).
- 지우는 것 · 콘솔 · DNS 는 전부 지형님 OK 를 받고 진행. 화면 글자는 영어 콘솔 기준(한글 콘솔은 메뉴 이름만 번역, 위치는 같음).
- 새 서버를 다시 세워야 하면 `deploy/server-setup.md` (반나절). 종료 뒤에는 서버로 되돌아가는 길이 없고, Supabase(Edge)가 원래 경로로 계속 돎.

## A. 며칠 전 — 되돌릴 수 있는 것만

앞의 두 줄(A1 · A2)이 핵심: **서버를 끄기 전에 트래픽이 이미 Edge 로 가 있어야** 앱이 안 끊김.

| # | 할 일 | 누가 | 화면 경로 · 명령 | 되돌림 | 끝 확인 |
|---|---|---|---|---|---|
| A1 | 스위치 표 전부 `edge` | 지형님(붙여넣기), SQL 은 세션이 준비 | [SQL 편집기](https://supabase.com/dashboard/project/gomrhctwjvttoqifxktt/sql/new)에 아래 SQL → Run | 가능 (캡처해 둔 이전 값으로 `update`) | 결과의 `mode` 가 전부 `edge` |
| A2 | pg_cron 이 Edge 를 이어받는지 | 세션 | 같은 편집기, 아래 확인 SQL. 5분 작업은 20분 안에 | — | `net._http_response` 에 wake-check · alarm-roll 200 이 새로 쌓임 |
| A3 | 앱 한 번 써 보기: 알람 저장 · 미리보기 · 일정 수정 | 지형님 | 웹 · 실기기 | — | 오류 없이 저장됨 (Edge 경로, 옛 APK 와 같은 길) |
| A4 | 예측 서버 주소 지우기 | 지형님 | [Edge 비밀](https://supabase.com/dashboard/project/gomrhctwjvttoqifxktt/functions/secrets)에서 `PREPARE_ML_URL` · `PREPARE_ML_API_TOKEN` 삭제 | URL 은 가능(다시 넣기). 토큰은 서버가 살아 있을 때만 의미(값은 서버 `ml.env` 에만 있음) | 미리보기가 P80 으로 정상 응답(예측 모델 출처 표시 없음) |
| A5 | 감시 일시 중지(삭제 아님) | 지형님 | [UptimeRobot](https://dashboard.uptimerobot.com) → 감시 2개(`/health/deep` · `/ml/health`) → Pause | 가능 (Resume) | 상태 Paused |
| A6 | 24 ~ 48시간 관찰 | 세션 | A2 의 SQL 을 다시 | — | wake-check · alarm-roll 200 이 계속 쌓이고 제안(`suggestion-generate`)이 다음 18:00 KST 에 돎 |
| A7 | (선택) pg_cron 을 M1 이전 모양으로 | 세션이 SQL 준비, 지형님 붙여넣기 | 본 레포 `supabase/ops/server-switch-rollback.sql` 통째로 실행 (여러 번 해도 같음, 다시 적용은 `server-switch-reapply.sql`) | 가능 | `cron.job` 에서 wake-check · alarm-roll · suggestion-generate 가 `invoke_edge_function` 을 바로 부르고 `suggestion-generate-safety` 가 없음 |
| A8 | 지울 것 목록 최종 확인 | 세션 | EC2 대시보드 Resources: 인스턴스 · 볼륨 · 스냅샷 · AMI · 탄력적 IP · 보안 그룹 · 키 페어 · CloudWatch 알람 (서울, 그리고 [Global View](https://console.aws.amazon.com/ec2globalview/home)로 전 리전) | — | 지울 것이 B 의 표와 같음 |

A1 SQL (표 `public.server_routes`, 열쇠 `(kind, name)`, M1 마이그레이션 기준)

```sql
-- 먼저 지금 값을 캡처해 둠 (되돌릴 때 필요)
select kind, name, mode from public.server_routes order by kind, name;
select * from public.server_route_users;   -- canary 대상

-- 전부 Edge 로 (함수 · 작업 모두 'edge' 를 허용함)
update public.server_routes set mode = 'edge' where mode <> 'edge';
```

A2 확인 SQL

```sql
select id, status_code, timed_out, created from net._http_response order by created desc limit 10;
select d.jobid, j.jobname, d.status, d.start_time
from cron.job_run_details d left join cron.job j on j.jobid = d.jobid
order by d.start_time desc limit 10;
```

(서버 스케줄러가 아직 `shadow` · `server` 로 돌고 있었다면 A1 로 `edge` 가 된 순간부터 서버는 그 작업을 안 함.)

## D. 남기는 것 · 정할 것

| 항목 | 상태 |
|---|---|
| Supabase Edge 함수 · Vault · pg_cron · `server_*` 표 · 앱의 스위치 분기(`callEdge`, 표가 `edge` 면 직접 Edge) | 남김. 서버가 없어도 원래 경로로 계속 돎. 표를 못 읽으면 `edge` |
| `notify` · `account-delete` · AI 함수 등 서버로 안 옮긴 것 | 처음부터 Edge 에 있음 → 종료의 영향 없음 |
| 도메인 `respecalarm.com` | AWS 비용이 아님(Cloudflare 도메인 연 요금). 갱신할지 지형님이 정함 |
| AWS 예산 알림 · 계정 | 알림은 무료라 남겨도 됨. 청구서 $0 을 확인한 뒤 **계정 닫기**(Billing → Account → Close account)는 선택 — 닫기 전에 남은 리소스가 0 인지 한 번 더. (계정 폐쇄 뒤 재개 가능 기간 등은 AWS 문서로 확인) |
| 서버 레포 | 필요하면 마지막에 보관(archive). 보관하면 설정 변경이 막히므로 B9 의 정리가 먼저 |

## 이 순서인 이유

- **표를 먼저 `edge` 로 (A1)**: 앱과 pg_cron 은 표를 보고 Edge · 서버를 고름. 서버를 끄기 전에 이미 Edge 로 가 있으면 끄는 순간 사용자가 느끼는 변화가 없음. 표를 못 읽어도 `edge` 로 동작하는 설계(M1)라 끝까지 안전한 쪽.
- **예측 주소를 서버 종료 전에 지움 (A4)**: Edge 의 `buildPlan` 이 죽은 주소로 예측을 부르면 연결이 안 될 때까지(최대 1.5초) 기다렸다가 P80 으로 답함. 주소를 지우면 기다림 없이 바로 P80.
- **DNS 를 탄력적 IP 해제보다 먼저 (B3 → B4)**: 해제한 IP 는 다른 AWS 사용자에게 다시 배정될 수 있음. 그때까지 내 DNS 가 그 IP 를 가리키면, 그 주소를 받은 남이 내 도메인 이름(`api.respecalarm.com`)으로 응답할 수 있음(dangling DNS). 레코드부터 지움.
- **인스턴스 종료 → 보안 그룹 · 키 페어 (B2 → B5 · B6)**: 인스턴스가 쓰는 보안 그룹은 지워지지 않음.
- **감시는 일시 중지 → 종료 후 삭제 (A5 → B8)**: 서버를 끄는 순간 감시가 "죽음" 메일을 보내지 않게.
- **GitHub 정리는 맨 뒤 (B9)**: 마지막까지 서버 배포 길을 쓸 일이 없는지 확인한 뒤에.
